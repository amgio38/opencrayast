# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Until 1.0 the project is
numbered `V0.YYYYMMDD.NNN` (crate version `0.YYYYMMDD.N`); see ADR-013.

## [Unreleased]

### Fixed

- The `audit` workflow no longer fails on every run after the first: it restores
  `~/.cargo/bin` from cache, and a bare `cargo install cargo-audit` then exited with
  "binary already exists". It now installs only when the binary is absent.

### Added

- `scripts/preflight.sh` (`make preflight`): runs, before any push, what CI runs on
  Linux — format, clippy, the whole workspace test suite, the docs check, the gate
  self-tests and the coverage gate — and refuses a tree with uncommitted files.
- `scripts/release.sh`: the one way to cut a release. It runs preflight, pushes
  `main`, waits for CI to finish green, and only then creates and pushes the tag and
  waits for the release and audit workflows. It refuses to reuse a tag.
  `docs/MAINTENANCE.md` documents the flow, including re-recording the MCP golden
  transcripts after a version bump.

## [0.20261007.001] — 2026-10-07

### Fixed

- **The one-line install no longer fails on Debian and Ubuntu.** The README
  command `curl -fsSL .../install.sh | sh` died with
  `sh: 44: set: Illegal option -o pipefail`: a pipe never reads the script's
  `#!` line, `sh` is dash on those systems, and `install.sh` began with
  `set -euo pipefail`. `pipefail` is now switched on only where the shell has
  it, so the installer runs under dash, bash and any POSIX `sh`. The README
  command is unchanged. The usage comments in `install.sh` also gave the
  script a path under a `scripts` directory that does not exist; they now match
  the README.

### Added

- `scripts/test-install-posix.sh` (CI step "Installer runs under POSIX sh",
  `make test-install-posix`): runs the real `install.sh` under `sh`, `dash` and
  `bash` — including the exact `curl | sh` shape over a local HTTP server —
  checks that every install URL in the README names a file in the repository, and
  carries a negative control that restores the old header and requires it to fail
  under dash.

## [0.20261002.001] — 2026-10-04

The first public import. `opencrayast` is an MCP server (plus a command-line
tool on the same core) that gives an agent a syntax tree instead of text, and
makes every change a two-step, reviewed, undoable operation.

**Platform support.** Reading and editing work on Linux, macOS and Windows.
Windows writes use a same-directory temp+rename; `fsync_dir` confirms the
directory still exists rather than issuing a POSIX directory sync. The isolated
parse worker is unported on every platform, so the parse budgets (size, wall
clock, depth, node count) are the only bound on a hostile source file today.

### Added

  rustc will not compile: a file that is not reached from `lib.rs` / `main.rs`
  by a `mod` (or `#[path]` `mod`) is a CI failure. The two leftover CLI sources
  that looked like the write path (`apply.rs`, `stdin_confirm.rs`) were never
  declared; they are gone. `scripts/test-check-undeclared-src.sh` plants an

  real ergonomic cost. It does **not** measure agent or first-call success rate,

  section) and six explicit manual sign-offs that are printed as `PENDING` on
  every run and turned into failures by `--require-manual`. Recorded run:
  **22 passed, 1 failed, 0 skipped**, exit 1, nothing signed off. `DENY-01` is
  reported `SKIP`, never `PASS`, when `cargo-deny` is absent. The self-test is
  **13/13**: each check is shown going red on its own single break, the manual
  gate is shown to refuse a partial sign-off, and the CI mode is shown to report
  `PENDING` without failing — because a checklist that is permanently red gets
  deleted rather than obeyed.
- `ROADMAP.md` with milestones M0–M8 and checked exit criteria.
- Governance files: licence (MIT), code of conduct, contributing guide, security
  policy, issue forms, pull request template and Dependabot configuration.
- `scripts/check-docs.sh` and `scripts/check-matrix.sh`, which keep the documents
  internally consistent.
- `scripts/check-coverage.sh` and `scripts/test-check-coverage.sh`: a **line-coverage
  floor of 80%** for the `core`, `edit` and `query` crates, enforced in CI on Linux and
  runnable locally with `make coverage` / `make coverage-gate`. This is the first time
  the 90% figure in `docs/TESTING.md` is backed by something that can go red. Measured
  on this tree: `core` 87.79%, `edit` 91.10%, `query` 93.48% — first-party code only,
  `tests/` excluded twice (by `--ignore-filename-regex` and again in the script). The
  floor is deliberately below every measurement: a floor set at today's number is
  theatre, not a gate. The floor constant lives in one place and CI does not
  hard-code it. The self-test proves the gate turns red on a below-floor crate, on an
  empty report, on a `tests/`-only report and on non-llvm-cov input, and pins that a
  crate sitting exactly at the floor still passes.
- Fuzz-style hostile-input tests for the safety-critical surfaces -
  path resolution, parsing, patterns/search, edit sets / templates, and the plan
  and journal deserialisers with the plan store - as deterministic seeded suites
  that plain `cargo test` runs on every machine:
  `core/tests/core_hostile_spec.rs`, `lang/tests/lang_hostile_spec.rs`,
  `query/tests/query_hostile_spec.rs`, `edit/tests/edit_hostile_spec.rs`, with the
  shared mutation toolkit in `crates/*/tests/common/fuzz.rs`. A failure prints the
  case index, the seed and the mutated input, plus a paste-ready replay line.
- Preview (`edit/src/preview.rs`): an edit request becomes a stored plan. The seven steps of
  `EDIT-MODEL` §Preview are not rearranged - arguments, then the read policy, then a size-capped
  read, then the edit set, then **E-1 validated in this layer whatever produced it**, then the
  new content in memory, then the gates on the bytes that would be written, and only then the
  plan, its derived id, the store and the diff data. It writes nothing to the workspace (E-12):
  the only write is `PlanStore::put`.
  - The **gates run at preview**, so a plan apply would refuse is refused now with the reason.
    The `stability` gate is the one with teeth: it re-applies the recorded edits and compares
    against the recorded `post_hash`, which is what makes it a proof rather than a formality.
  - **Determinism**: nothing time- or build-dependent is hashed, files are stored by their
    workspace-relative path, and files and edits are sorted - so the same content and request
    give the same plan id on every platform.
  - **Deduplication is by file identity** (device + inode, or the Windows file id), never by
    path spelling, so a hard link or a case alias cannot put two conflicting edit sets for one
    file into a plan.
  - A file that cannot be edited during a scan is **counted with its reason**; a file the
    caller named explicitly is an error, because then the caller asked about that file.
  - Symbol edits resolve to exactly one node or are refused: `ambiguous` names every candidate
    and `not_found` points at `ast_outline`. The tool never guesses.

### Fixed

- **Two corrections to the Windows path rules, and the class of names Windows cannot spell.**
  Both were found by the Windows CI job, and the first is a correction to *our own* rule
  rather than a gap in the code:
  - `\\?\C:\x` is **not** a network path. It is a local volume in the verbatim
    (extended-length) spelling, and it is what Windows' own `canonicalize` returns for an
    ordinary `C:\...` root - so the rule that refused "two leading separators" as UNC
    refused the most common Windows root there is, and two of our own tests failed on the
    Windows job because of it. A verbatim path is now allowed when it is a drive letter,
    a colon and a separator (`\\?\C:\x`, any letter, either separator, any case). Everything
    else under that prefix keeps the refusal, and each for its own reason: `\\?\UNC\srv\share`
    is a network location wearing the verbatim prefix, `\\?\GLOBALROOT\...` reaches the
    block-device namespace, `\\?\Volume{...}\...` names a volume GUID for which a caller has
    no canonical form to hold, and `\\.\...` is the device namespace outright.
  - The exception is for **operator-supplied roots only**, and for an agent-supplied
    relative path a `\\?\` or `\\.\` prefix is now refused *wherever it appears*, not just
    at the front. Two reasons, and the second is the real one: a path an agent supplies is
    never canonicalisation output, so the prefix there is only ever input and costs nothing
    to refuse; and `\\?\` means "the rest of this string is not normalised", so the double
    separator stops `..` collapsing and `a/\\?\../..` reaches the object manager as a real
    parent reference while looking like an ordinary relative path. **This costs something on
    Unix**, like the colon rule below: a file literally named `\\?\x` becomes unreachable.
  - A name Windows cannot spell now answers `outside_workspace` instead of `io_error`.
    `resolve_read(">>")` failed inside `open` with `ERROR_INVALID_NAME` on Windows, while a
    merely absent path answered "not found": the same answer in two codes, so the code told
    an attacker *which names are illegal*. The fuzzer stops at its first failure, so a class
    found this way is a class whose neighbours are unreached - the whole class is now refused
    at the string layer instead of one case at a time: the seven characters Windows rejects
    (`< > " | ? *` and control characters), a trailing dot or space (Windows silently strips
    them, so `foo.` *is* `foo`, and the name the boundary checked would not be the name the
    file system opened), and the reserved device names `CON` `PRN` `AUX` `NUL` `COM1`-`COM9`
    `LPT1`-`LPT9` including the superscript spellings Windows also accepts - in any case,
    with any extension, and with a trailing dot or space. This check is **Windows-only**:
    `con.go` and `aux.rs` are ordinary files on Unix and a real project has them, so refusing
    them there would be refusing the code base rather than defending it. The rule is a pure
    string function tested against its whole table on every platform, and consulted under
    `cfg!(windows)` so it is compiled and linted everywhere.
- `docs/TESTING.md` claimed (SUP-02) that grammar crates were pinned and licence
  recorded, and named `scripts/check-docs.sh` as the thing that proved it. That
  script checks links, personal paths, language and ticket references — it never
  read `Cargo.lock`, and no check of any kind enforced the claim. The claim is now
  true and its target is a check that actually enforces it.
- `THIRD-PARTY-LICENSES.md` was stale: the generator now lists 48 third-party
  normal dependencies rather than 42, because the CLI crate's `clap` tree had been
  added without regenerating the inventory.

- **Windows-shaped paths are now refused on the string, on every platform**, before any
  filesystem call. Found by the Windows CI job running the fuzz-style suite
  (`core_hostile_spec`), where two real gaps showed up that Linux and macOS cannot see,
  because there those strings are merely odd file names:
  - `C:.:\WiWi` and every other *drive-relative* spelling (`X:` with no separator after
    the colon) reached the filesystem and came back `io_error`, where a path that is
    merely absent comes back `outside_workspace`. One question, two answers - a probe
    oracle. On Windows `C:foo` is not a file called `C:foo`; it is relative to the
    current directory *of drive C*, a directory the process chose and the caller never
    mentioned. As a `--workspace` or `--read-root` it is a location escape, not a typo,
    so the root check refuses that shape too - while `C:\proj`, the most ordinary root
    on Windows, stays legal.
  - `\` and `//` (and the `\/`, `/\` mixtures a JSON payload or URL parser produces) are
    UNC paths. Canonicalising one makes Windows resolve a host name and open an SMB
    session: for an attacker-supplied host, a DNS lookup and an NTLM challenge sent to a
    machine they control, plus a hang until the timeout expires. `workspace_id` and
    `Boundary::new` now judge the string before canonicalising, and answer with one
    message for every spelling so the refusal is not an oracle of its own.
  - A colon in any component (`file.txt:stream`, `dir/a:b/c`) is an NTFS alternate data
    stream - bytes that belong to no file you can reason about, and a write target no
    `stat` mentions. Refused everywhere, which **costs something**: a Unix file whose
    name contains a colon is no longer reachable. Paid deliberately, for one rule that
    behaves identically on every platform and is therefore testable on every platform;
    see the path rules in `TOOLS.md`.

Two of those proofs are worth reading twice, because they are about the *tests* rather
than the code:

- Rule 1(a) is caught by predicate-level unit tests only. On the resolve path rule 2
  already refuses every drive-relative spelling, because each of them contains a colon -
  so the end-to-end test passes either way. Rule 1(a) stays because it is the statement
  of what a drive letter *is*, and because a rule that only one other rule happens to
  cover today is one edit away from being uncovered.
- "Refused before the filesystem was consulted" cannot be shown by the error code: a
  root that does not exist is `invalid_args` too, so a canonicalisation that ran would
  produce a passing test. The tests therefore assert the refusal *wording*, which only
  the string check can produce. Before that change the `check_root` mutation proof
  passed with the check deleted.
